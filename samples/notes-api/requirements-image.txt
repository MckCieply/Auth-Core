# The sample's own dependencies. The package itself is not listed: a product installs it from a tag of the Auth-Core
# repository with this line (docs/integration/python-fastapi.md, step 1):
#
#   auth-core-fastapi @ git+https://github.com/MckCieply/Auth-Core@python-v0.1.1#subdirectory=clients/python
#
# The Dockerfile of this sample installs it from the clone (clients/python) instead, so that the sample builds
# from one clone, with no tag and no GitHub.
#
# The same packages at the same exact versions as requirements.txt (a test of the sample keeps the two equal), each with
# the hash of its files: the Dockerfile installs this with --require-hashes and --only-binary, so a different file under the
# same version, or a package that is not in this list at all, stops the build. The hashes are those of the wheels for Python 3.12
# on Linux, x86_64 and aarch64 (a pure Python package has one wheel for both), so this list is for the image, not for Windows or
# macOS. To update: change the pins in both files, then make the hashes again: `pip download --only-binary=:all: --no-deps
# --python-version 3.12 --platform manylinux_2_28_x86_64 --platform manylinux_2_17_x86_64 --platform manylinux2014_x86_64
# -r <the pins> -d <a directory>` (and the same for aarch64), and `pip hash` for each file.
#
